## Dev workflow
- [ ] **Conversational capture → safe structured write to the build queue.** Goal: while journaling (Keeper) or in any persona session, name a build task/idea out loud and have the agent capture it into the backlog — *without* letting the LLM free-edit files (no unrecoverable mistakes). Architecture decided 2026-06-23:
  - **Safety lives in a constrained write path, not in prose.** The agent never edits the file; it calls *one narrow operation* — `add_todo(text, theme, source?)`, a small script or Flask endpoint — that validates the fields and appends atomically via `store.py`. The model fills slots; code does the write.
  - **Source of truth = a JSON in `personal/data`** (auto-committed hourly by `git_backup.sh`); `dev_todo.md` becomes a *generated, read-only view* of that JSON. Why: `dev_todo.md` lives in skeleton, which the cron only *pushes*, not auto-commits → direct edits have no backup. Moving the truth into the personal vault fixes recoverability. (Mirrors the existing "send to ideas" → `IDEAS.md` append flow.)
  - **Five safety layers:** append-only (never rewrite/delete) + schema validation + *you-confirm-before-it-lands* (a pending step / confirm tap = the "no irreversible mistake" guarantee) + `store.py` atomic writes + git history.
  - **Package the capability as a `context: fork` skill** (isolated subagent, fixed prompt, can't see/touch other files) — first real use of the existing "fork subagent skill" todo. CLAUDE.md/skill says *when*; the script/endpoint is the safe *what*.
  - **Flow:** journal naturally → task surfaces → agent proposes structured `{text, theme}` → you confirm → runs the one command → appends to JSON → md regenerates.
  - **Smallest shippable slice:** just the `add_todo` script + confirm (no fork, no pending queue) — ~1 hr. **Build after the job settles** (post-July fallow work, not pre-start). Also a dogfood of the product's core conversational-capture thesis.

- [ ] Make `exocortex-tmux.service` the single owner of the tmux server (defuses a session-killer footgun). Today the live tmux server (socket `/tmp/tmux-1000/default`) is spawned by `ttyd` and lives in ttyd's cgroup, while `exocortex-tmux.service` sits in a `failed` state (historical OOM-kill) but still claims ownership via `ExecStop=tmux kill-server`. Result: `systemctl restart exocortex-tmux` — the natural reflex to clear the failed unit — kills the whole server and every claude session at once. Fix: (1) make session creation idempotent (`tmux has-session -t chat || tmux new-session -d -s chat -c /opt/exocortex`) so the oneshot stops failing; (2) ensure this service starts the tmux server (ordered `Before=ttyd`); (3) change `ttyd_connect.sh` to *attach* to an existing session instead of spawning a new server. Then ttyd restarts become permanently irrelevant to running sessions — the proper version of the `KillMode=process` band-aid added during the 2026-06-11 nest migration. Do it deliberately (it touches the live session server), not casually.
