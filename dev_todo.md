Today the live tmux server (socket `/tmp/tmux-1000/default`) is spawned by `ttyd` and lives in ttyd's cgroup, while `exocortex-tmux.service` sits in a `failed` state (historical OOM-kill) but still claims ownership via `ExecStop=tmux kill-server`. Result: `systemctl restart exocortex-tmux` — the natural reflex to clear the failed unit — kills the whole server and every claude session at once. Fix: (1) make session creation idempotent (`tmux has-session -t chat || tmux new-session -d -s chat -c /opt/exocortex`) so the oneshot stops failing; (2) ensure this service starts the tmux server (ordered `Before=ttyd`); (3) change `ttyd_connect.sh` to *attach* to an existing session instead of spawning a new server. Then ttyd restarts become permanently irrelevant to running sessions — the proper version of the `KillMode=process` band-aid added during the 2026-06-11 nest migration. Do it deliberately (it touches the live session server), not casually.
